# Agent Usage Monitor Rust project instructions

- Keep the Rust workspace under `rust/`; use stable Rust and preserve the package metadata.
- Keep provider protocols in the Core crate and UI behavior in the Slint crate.
- Keep Claude integration opt-in and OFF by default in every distribution. Preserve the official local status-line JSON bridge and allow optional background retrieval through the installed Claude CLI's `claude -p --no-session-persistence /usage` command only when explicitly enabled by the user. Never read credentials/transcripts, access private OAuth APIs, issue model prompts, or change global Claude settings. For confirmed-unpackaged EXE builds, the listener may be enabled by the existing explicit `--enable-claude-bridge` launch flag or by a new explicit, persisted AUM Settings control; for the Microsoft Store (MSIX) build, which cannot take launch arguments, retain the existing off-by-default Settings toggle `claude_bridge_listener_enabled`. EXE and MSIX opt-in state must remain distribution-specific. Any v0.2.0 installer migration must preserve only a previously explicit opt-in, must never infer opt-in from Claude provider enablement alone, and must not silently enable the bridge for users who did not opt in. Keep bridge control independent of provider credentials and global CLI configuration.
- Keep one binary for all distributions; choose MSIX-specific behaviour at run time from package identity (`packaged::is_packaged()`), never by changing the EXE builds' behaviour (see `docs/msix.md`).
- Do not add installer or autostart behavior without an approved project scope.
- Never commit secrets, generated binaries, or local build output.
